# RFC 0000: Template

- **Status:** Draft | Accepted | Superseded by RFC-XXXX
- **Date:** YYYY-MM-DD
- **Supersedes:** —

## Context

What is true about the system today that makes this decision necessary? Facts,
not opinions. If a prior RFC or an existing subsystem constrains the choice, name it.

## Problem

The specific question this RFC answers, stated so that a reader six months from now
knows what would have gone wrong without a decision.

## Decision

What we are doing. Normative language ("MUST", "MUST NOT", "MAY") for anything that
is a rule other components must obey. Include the concrete shape — schema, interface,
signature — not just the intent.

## Alternatives Considered

Each alternative with the honest reason it lost. An RFC with no real alternatives is
usually a decision that wasn't actually made.

## Consequences

Both directions. What gets easier, and what this costs us — including work that becomes
harder or impossible. If a downside is accepted deliberately, say so here rather than
discovering it later.

## Migration Strategy

Only if this changes something that already exists. How existing artifacts, schemas, or
code move to the new decision without a flag day.

## Open Questions

Things deliberately left unresolved, with the evidence that would resolve them. An open
question here is a promise to revisit, not an oversight.

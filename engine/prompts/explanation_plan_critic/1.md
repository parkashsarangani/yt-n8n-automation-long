# Core question

**Does this visual earn the seconds it occupies?**

The new production contract is concrete/domain representation first. A scene is weak when it turns a readily depictable object, mechanism, quantity, or spatial arrangement into labels and arbitrary geometry.

The decisive anti-generic test:

> Could this same picture serve an unrelated topic if only its labels changed?

If yes, it is weak.

Also reject a scene whose `entity_refs` invent identities, point outside the ontology, or substitute generic icons/shapes for a depiction already defined by the ontology.

# Failure modes

- `generic-visual`: generic visual vocabulary unrelated to the episode's actual subject.
- `over-abstracted`: narration describes a readily depictable physical/scientific/spatial/quantitative phenomenon but the plan does not use the corresponding semantic representation.
- `label-dependent`: the picture carries little or no meaning without reading labels; the words are doing the explanatory work.
- `missing-causal-action`: a semantic scene names the right things but `visual_actions` do not show the state change or mechanism asserted by narration.
- `wrong-representation`: `representation_mode`/`scene_blueprint` cannot honestly depict the claim, or a better supported semantic renderer clearly exists.
- `motion-without-information`: authored actions only move/decorate objects without changing explanatory state.
- `claim-mismatch`: visual claim, relation direction, before/after, or state contradicts the spoken claim.
- `static`: the scene should change over the spoken turn but the plan provides no meaningful progression.
- `repeats-neighbour`: near-identical to adjacent scene despite a meaningful change in the narration.
- `unauthored-structure`: legacy relational metadata claims a relationship primitive but provides no actual relations where relations are required.
- `overfull-label`: state/key text is authored as a sentence rather than a compact phrase.
- `none`: no defect.

Any failure mode other than `none` => `verdict: "weak"` and overall `revise`.

# Representation-specific review

## container-object
Must visibly encode the container/medium, the object, and the key positional/state outcome. `drop`, `rise`, `sink`, `fill`, `settle`, etc. should correspond to narration. A floating object represented as two labels connected by an arrow is `over-abstracted`.

## before-after-object
The same object identity must survive the change. If the two states are merely two unrelated labels, it is `label-dependent`.

## molecular-system
Use only when molecular geometry/motion/bonding is explanatory. Actions should include meaningful processes such as `slow`, `rotate`, `bond`, `break-bond`, `rearrange`, `cluster`, `scatter`. If the narration is macroscopic, this may be the wrong representation.

## lattice
The open/repeated ordered structure and spacing must be the claim. A generic network is not a lattice.

## mass-volume-comparison
The viewer must be able to see what is preserved (same count/mass/items) and what changes (occupied volume/size). If the representation swaps different objects, the comparison lies.

## cross-section
Layer/location/surface/depth is part of the explanation. Actions should change position/layer/state in a physically meaningful way.

## animated-statement
This is a valid intentional fallback when the available semantic renderers cannot depict the concept honestly. Do not mark it weak merely because it is text. Mark it weak only when a supported concrete representation clearly exists or when the statement is verbose/unfocused.

# Voice anchoring

For every non-text scene, each action should use a short `anchor_phrase` actually found in that scene's narration. If anchors are vague, duplicated, or not present, flag `missing-causal-action` because timing will fall back to generic distribution rather than phrase alignment.

# Bookends

Opening should pose the visual question using concrete entities when possible. Final recap must resolve the same mechanism/entities; a generic slogan/ring is weak even if the text is good.

# Suggested fixes

For every weak scene, name exact fields and changes. Do not say `make it more engaging`.

Good:
- `change representation_mode to domain-model; scene_blueprint to molecular-system; add actions slow/bond/rearrange anchored to the three clauses`
- `change scene_blueprint to container-object; actor ice cube drop then rise toward water surface`
- `no supported semantic renderer exists for this abstraction; change representation_mode to kinetic-text and scene_blueprint to animated-statement`

Bad:
- `use a better primitive`
- `add more motion`
- `make the diagram clearer`

# Verdict calibration

- `strong`: visual makes a relationship/mechanism/state change substantially clearer than narration alone.
- `adequate`: correct, specific, progresses, earns its time.
- `weak`: any failure mode above.

Most good episodes should contain mostly `adequate` scenes and a smaller number of `strong` scenes. Do not manufacture criticism when a scene is already appropriate.

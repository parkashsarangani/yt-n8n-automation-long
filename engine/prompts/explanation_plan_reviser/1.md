# Revision fidelity

Every scene marked weak must come back materially different in the fields needed to fix the review. Every scene not marked weak must be copied unchanged. Do not churn working entity spelling, acting, or semantic plans.

# Non-negotiable fallback rule

Do NOT fix a weak semantic scene by choosing another generic node/box/relationship picture.

If a concrete/domain/quantitative/spatial renderer can depict the narration, use it. If none of the supported semantic blueprints can depict the idea honestly, change to:

- `representation_mode: "kinetic-text"`
- `scene_blueprint: "animated-statement"`
- `visual_actions: []`

Animated explanatory text is the fallback. Arbitrary geometry is not.

This fallback is never available for scene 0. If scene 0 is flagged weak and no supported blueprint fits perfectly, pick the closest honest concrete/domain/quantitative/spatial fit rather than falling back to `kinetic-text`. This is enforced as a hard release-gate failure.

# Supported repairs

## over-abstracted / generic-visual / wrong-representation
Change `representation_mode` and `scene_blueprint` to the most concrete supported renderer that can make the claim visually true:

- physical object in medium/container -> `concrete-scene` / `container-object`
- concrete state transformation -> `concrete-scene` / `before-after-object`
- molecule/bond/orientation mechanism -> `domain-model` / `molecular-system`
- open/repeating ordered structure -> `domain-model` / `lattice`
- preserved amount/count with changed occupied volume -> `quantitative` / `mass-volume-comparison`
- layered/surface/depth mechanism -> `spatial` / `cross-section`
- unsupported abstraction -> `kinetic-text` / `animated-statement`

Update `visual_claim` to exactly what the new representation proves.

## label-dependent
Make the visual state readable through object position, structure, count, geometry, or physical transformation. Reduce reliance on labels. If that cannot be done with supported renderers, use animated-statement rather than a labelled pseudo-diagram.

## missing-causal-action
Add/rewrite 1-6 `visual_actions`. Each must have:
- canonical actor;
- real explanatory action;
- target or empty string;
- short literal `anchor_phrase` from narration.

Use actions such as rise/sink/drop, expand/contract, freeze/melt, assemble/disassemble, bond/break-bond, rearrange, flow, cool, slow, settle. Never add decorative pulse/wiggle/glow actions.

## motion-without-information / static
Replace decorative movement with actions that change explanatory state. The final action should reveal the consequence of the spoken line.

## claim-mismatch
Correct `visual_claim`, action direction, state, relation direction, or before/after so the picture states exactly what narration states.

## repeats-neighbour
Do not change the unflagged neighbour. Change this scene's representation only if the narration has genuinely changed type; otherwise keep representation continuity and make the state/action materially advance instead of introducing arbitrary novelty.

## overfull-label
Shorten state/key text to compact phrases without changing the semantic representation.

# Voice alignment

`anchor_phrase` must occur in that scene's narration. Prefer the shortest unique phrase that anchors the exact causal moment.

# Stable identities

Keep `model_elements` exact spelling stable whenever the same entity returns. Do not rename `water molecule` to `H2O molecule` mid-episode unless the script truly introduces a distinct entity.

# Legacy metadata

Keep required primitive/operation/relation fields valid for compatibility and ancillary selection logic, but never let them dictate a worse semantic representation.

`numeric_value` remains mandatory when `visual_operation` is `counter` or `visual_primitive` is `quantity` and should be omitted otherwise.

# Character and bookend invariants

- Scene 0 remains a `character-hook`, bookend, both characters, and never `kinetic-text` / `animated-statement`.
- The last CONTENT scene (the scene right before an `is_outro` scene, if one exists) remains recap/payoff/bookend/both characters.
- If the script's final scene carries `is_outro: true`, its plan entry remains `composition_mode: "character-room"`, `character_cut_in: "both"`, `scene_role: "character-reaction"`, with no diagram fields — never merge it into the recap scene, never drop it, never give it a diagram.
- Middle character cut-ins remain <=35% (the outro scene renders through the cartoon pipeline, not the explanation one, so it is not part of this ratio).
- Full-model mechanism scenes normally have no characters.
- Required actor performance fields remain present on bookend/reaction/character-room scenes.
- A middle scene with a weak or missing diagram is a candidate for `composition_mode: "character-room"` (both characters full-screen in a real room, no diagram) rather than forcing a generic representation onto it or shrinking the characters into a bust panel -- but only when no honest concrete/domain/quantitative/spatial representation fits; it renders through the cartoon pipeline so it is not measured by the <=35% cap, and it still requires `character_cut_in: "both"` and no `representation_mode`/`scene_blueprint`/`visual_claim`/`visual_actions`.

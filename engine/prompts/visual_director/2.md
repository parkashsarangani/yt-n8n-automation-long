FULL-EPISODE COVERAGE — NON-NEGOTIABLE
This is production, not the old RFC 0010 benchmark window.
- Cover EVERY narration scene in `script`, from the first spoken word through the closing takeaway/outro.
- Never stop at 90–120 seconds. There is no benchmark window in production.
- Within each scene, the beats' `narration` strings concatenated in beat order MUST reproduce that scene narration exactly: same characters, words, punctuation and numbers; no gaps, no overlaps, no paraphrase.
- `start_sec`/`end_sec` are provisional scene-relative offsets only. The downstream aligner replaces them with exact character-aligned voice timings.
- Usually use 1–2 beats per narration scene. Split further only when the semantic visual job actually changes. Prefer roughly 4–10 seconds per beat over gratuitous 2-second churn. A visual may hold across a pause or sentence when the same idea is still being explained.
- Beat indices reset per scene. IDs are globally sequential (`beat_001`, ...).
- Keep the JSON compact enough for a full long-form episode: exactly 3 materially different `query_variants` and exactly 3 materially different `generation_variants` per beat. Do not repeat prose across fields when a short precise phrase is enough.

CORE RULE
For every beat answer separately:
1. SEMANTIC — what must visibly be present for the exact narration to make immediate sense?
2. RETENTION — what is the strongest non-misleading way to show it now, considering the preceding 20–30 seconds?
A beautiful but merely topical image is failure. Generic boxes/cards that do not represent the narrated entities or relationship are failure. A generic crowd/location shot that only implies the required action is failure.

PRODUCTION VISUAL GRAMMAR — ILLUSTRATION FIRST
This pipeline produces illustrated stories. Keep the episode visually coherent across the entire runtime.
- `generated_image` is the default authored visual for concrete narrative, historical, emotional, character, object and specific physical scenes. For production generated images set `routing.image_style="illustration"`.
- `motion_graphic` is preferred for quantities, scale, maps, timelines, processes, cause/effect, comparisons and transformations that are genuinely clearer as deterministic explanation graphics.
- `stock_video` is exceptional: use it only when authentic footage is itself evidence or location truth materially improves understanding. Do not use stock merely because it is easy to search.
- `generated_video` is exceptional and must always have a cheaper semantic fallback. Paid generated video is blocked by production policy; do not design a beat that only works if generated video exists.
- Never make preferred and fallback identical.

LOCKED ILLUSTRATION STYLE
When `intent.image_style` is present, EVERY `generation_prompt` and EVERY `generation_variants[]` entry for an illustrated beat must explicitly carry the same style language. Never drift between styles mid-episode.
Use these production identities:
- `ink_wash_stickman`: hand-drawn pen-and-ink illustration, muted sepia/ochre/dusty-green wash, faceless minimal human figures, detailed environments/objects/animals, visible paper grain, wide off-centre composition.
- `flat_comic_expressive`: hand-drawn vintage editorial cartoon, rough black ink/charcoal contours, expressive readable faces, simplified anatomy, flat muted navy/slate/brick-red/ochre blocks, cream textured paper, handmade edges.
- `documentary_sketch`: restrained charcoal and graphite reportage sketch, realistic proportions as drawing, observational setting detail, muted grayscale, paper tooth and cross-hatching.
- `watercolor_storybook`: soft watercolor storybook illustration, visible brushwork and color bleed, simplified painterly figures, warm pastel palette, breathing off-centre composition, paper texture.
- `noir_charcoal`: high-contrast charcoal and ink illustration, heavy chiaroscuro, expressive rough marks, restrained monochrome palette, cinematic negative space.
If intent has no style, keep one coherent editorial-illustration grammar for the whole episode; never alternate random art styles.

VISUAL CONTRACT
- `required`: concrete observable entities/states, not abstractions. Example: "same red suitcase beside the commuter" rather than "travel".
- `required_action`: the visible action/state. Blank only when genuinely absent.
- `forbidden`: plausible weak/misleading filler specific to this beat.
- `viewer_takeaway`: what the visual itself must make intuitive.
The resolver treats these as contracts, not suggestions.

ROUTING BY VISUAL JOB
- Concrete story/action/character scene -> illustrated `generated_image` unless authentic evidence footage is genuinely better.
- Numbers/scale/comparison/map/timeline/process/cause-effect -> `motion_graphic` with a drawable `semantic_scene`.
- Physical action plus abstract consequence -> keep the physical scene visible; use an illustrated action scene with restrained deterministic annotation rather than replacing the action with full-screen boxes.
- `stock_video` may be preferred only when the footage can visibly prove the required action/place/evidence.
- `generated_video` only for a true high-value motion-dependent hook/reveal/turn/payoff; always author a strong non-video fallback.

CANDIDATE DIVERSITY
Workers do not invent semantics. Author exactly three useful alternatives.
- `query_variants`: 3 materially different concrete searches, not synonyms.
- `generation_variants`: 3 self-contained illustrated compositions preserving the exact same facts/entities/style while varying viewpoint, staging or moment.
- `generation_prompt`: strongest default composition, normally one of the variants.
- `generated_video_prompt`: exact physical motion/camera movement; no fake readable UI.
- `motion_graphic_brief`: deterministic objects/data/spatial relationship/start state/transformation/end state.
Keep all candidate strings concise and put the most important subject/action/style first; free image providers enforce prompt-length limits.

SEMANTIC SCENE — REQUIRED WHEN MOTION GRAPHIC IS PREFERRED OR FALLBACK
`motion_graphic_brief` is not drawable by itself. Populate `asset_brief.semantic_scene` with the literal data that must be drawn.
Supported kinds:
- `scale_comparison`: axis + numeric markers, with units/rates/times/equation when narrated.
- `timeline`: 2–5 named nodes.
- `process`: 2–5 named ordered steps.
- `before_after`: explicit before and after states.
- `quantity`: named numeric items.
- `kinetic_phrase`: only when no richer structure exists; 1–3 short lines, exactly one emphasized.
Rules:
- Never invent numbers not stated by narration.
- Every marker/item has a real numeric value when the kind requires one.
- `caption` is a short visible phrase, never a full narration sentence.
- Every timeline/process/cause chain must expose meaningful short labels during playback; never leave explanatory primitives anonymous.
- Unsupported or insufficient structure must degrade to truthful kinetic text, never generic geometry.

CUMULATIVE EXPLANATIONS
When consecutive beats build one explanation, use the same `semantic_scene.sequence_id`; set `continuation=true` after the first. Later beats add to the established composition rather than resetting it. Stable node/marker/step IDs must be reused exactly.

CONTINUITY — FIRST IDENTITY WINS
Use stable `continuity.group` and stable entity IDs whenever a person/object/location recurs.
- The first non-empty `continuity.identity` for a group is authoritative for the episode. Later beats must not redefine it.
- Repeat stable physical cues in every generated concept for that recurring entity: approximate age/presentation, hair, wardrobe, distinguishing object/color and environment when relevant.
- Do not switch actor, clothing, suitcase, phone, vehicle, building or other recurring identity without narrative reason.
- Anonymous stock must never establish a recurring hero identity.
- If exact identity matters, prefer authored illustration over stock.

TEXT / LABELS / AI TYPOGRAPHY
Readable deterministic labels, dates, numbers, equations and map labels are allowed when needed for explanation. What is forbidden is generated pseudo-writing.
- Do not ask image/video models to render critical readable text.
- Keep generated screens/signs/papers blank or unreadable and let deterministic renderer text carry required labels.
- Do not substitute long caption cards for actual explanatory content.

RETENTION / VISUAL VARIETY
Plan against the preceding 20–30 seconds.
Populate `composition`, `camera_treatment`, `subject_placement`, `explanatory_pattern`, `novelty_required`, and `visual_change_strength` truthfully.
Avoid long runs of the same framing, mode, centered subject, camera treatment or explanatory grammar. Variety never overrides continuity or semantic truth.

OPENING, HERO BEATS, PAYOFF
- The opening must visually fulfill the package promise immediately; no generic establishing filler.
- Use `hero_role` only for genuine hook / first-escalation / low-point / turn / payoff beats.
- The final takeaway/payoff must not be visually inert. The closing beat must contain a visible transformation, reveal, comparison, resolved state, or other concrete payoff stronger than the setup. Do not end on a generic background with captions alone when the narration contains a conclusion that can be shown.

FREE-FIRST / COST-AWARE AUTHORING
The runtime tries cache/reuse/free sources before paid image fallback and blocks paid generated video by default. Your plan must make that routing safe:
- Every expensive/generated preference has a semantically valid cheaper alternate.
- A fallback is an authored alternate representation, not permission for unrelated filler.
- Do not choose generated video as the only truthful way to communicate a beat.
- Generated-image prompts must remain useful on a free FLUX-class image model: concrete subject, action and composition first; concise style; no prose padding.

QUALITY CHECK BEFORE RETURNING
Silently repair the full plan if any of these are true:
- any script scene or spoken word is not covered;
- the plan stops after a benchmark window instead of the full episode;
- beat narration paraphrases the script;
- a visual could fit ten unrelated sentences;
- required fact/action is not visibly represented;
- stock merely implies rather than shows the required action;
- generated concepts omit the locked episode illustration style;
- query/generation variants are near-duplicates;
- three or more recent beats repeat visual grammar without continuity reason;
- recurring identity or entity IDs drift;
- abstract explanation is routed to generic stock;
- physical action is replaced by meaningless boxes/cards;
- motion graphic lacks a drawable semantic_scene;
- timeline/process/cause entities are unlabeled;
- cumulative beats reset instead of sharing sequence_id and stable IDs;
- generated imagery relies on pseudo-text;
- generated video is used without a strong non-video fallback;
- final takeaway has no visible payoff/transformation.

Return only the schema-conforming artifact.

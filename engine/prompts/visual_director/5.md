HARD CONTRACTS
- Cover EVERY script scene in order. Reset `beat_index` per scene; IDs are globally sequential `beat_001`, `beat_002`, ...
- Use enough semantic beats for measured voice duration: target roughly 4–10 seconds; about ceil(scene_voice_seconds/10), normally 1–3 per scene.
- `start_sec`/`end_sec` are provisional scene-relative offsets. The engine aligns them to measured voice.
- The engine canonically derives the exact beat narration bytes from the immutable approved scene text using your beat count and phrase boundaries. Put the intended source segment in each `narration` field, never invent/paraphrase story facts, but DO NOT spend output effort manually reproducing byte-perfect punctuation.
- Exactly 3 materially different `query_variants` and 3 materially different `generation_variants` per beat.
- `routing.preferred` and `routing.fallback` MUST differ. Both modes must have usable briefs. Never declare an alternate you cannot actually render.

REPRESENTATION SELECTION
Choose by information structure, not habit:
- `generated_image`: DEFAULT for concrete people, places, objects, evidence, emotional moments and physical action. Keep the episode's locked illustration style.
- `motion_graphic`: ONLY when relationships/quantities/order are what the viewer must understand.
- `stock_video`: exceptional, when authentic footage/location truth is valuable.
- `generated_video`: exceptional motion-dependent hero moment; paid video is normally disabled and a strong non-video alternate is mandatory.

When using `motion_graphic`, choose the actual semantic structure:
- `timeline`: chronology/time ordering only.
- `process`: ordered mechanism/stages.
- `cause_chain`: A causes B causes C; explicit directed edges.
- `branching`: one state/input produces two or more visible outcomes; one source node MUST have >=2 outgoing edges.
- `comparison`: side-by-side alternatives/states; not chronology.
- `before_after`: visible transformation or resolved state, especially useful for payoff.
- `relationship_graph`: entities and their links matter more than sequence.
- `sequence`: ordered logical steps without a time axis.
- `scale_comparison`: common numeric axis + values/units.
- `quantity`: named numeric values.
- `kinetic_phrase`: rare intentional emphasis only; NEVER a generic explanatory fallback.

OBVIOUS SEMANTIC MISMATCHES ARE HARD-REJECTED
- divergent outcomes / two branches / one outcome vs another -> `branching`, not timeline/process.
- cause/consequence -> `cause_chain` or `branching`, not chronology-only timeline.
- A vs B / contrast -> `comparison`, `scale_comparison`, or `before_after`.
- visible transformation / apparent-vs-actual resolution -> `before_after` or another explicit reveal structure.
- a headline or generic five-node line cannot satisfy an explanatory/hero/payoff beat.

DOUBLE-DOSE STYLE REGRESSION RULE
If narration describes one broken workflow producing different downstream outcomes (for example a repeated dose on one branch and a missed patient on another), render a real `branching` semantic scene: stable labelled source node, separate labelled outcome nodes, and explicit edges. A linear timeline is wrong.

VISUAL CONTRACT
- `required`: concrete observable entities/states.
- `required_action`: what must visibly happen/be related.
- `forbidden`: plausible weak/misleading filler.
- `viewer_takeaway`: what the visual itself must make intuitive.
A merely topical image, location filler, decorative boxes, or narration-restating card is failure.

SEMANTIC SCENE DATA
For motion graphics populate concise deterministic data only; renderer owns geometry.
- `cause_chain`, `branching`, `relationship_graph`: stable `nodes` + directed `edges` (`from`,`to`, optional short label).
- `comparison`, `timeline`, `sequence`: stable labelled `nodes`.
- `process`: stable ordered `steps`.
- `before_after`: explicit labelled `before` + `after`.
- `scale_comparison`: axis + numeric markers; never invent numbers.
- `quantity`: numeric items.
Every explanatory entity must be labelled. Reuse stable ids across a cumulative `sequence_id`; set `continuation=true` when adding to the same composition.

DO NOT DEFAULT EVERYTHING TO TIMELINES
Across an episode, repeated semantic graphics should reflect genuinely repeated semantics. If consecutive beats have different information structures, use different structures. Prefer a concrete illustration whenever a physical scene/action communicates the point better than a diagram.

ILLUSTRATION STYLE / CONTINUITY
If `intent.image_style` exists, every generated-image prompt/variant must carry the same style identity. First non-empty `continuity.identity` wins. Reuse stable `continuity.group` and entity ids for recurring people/objects/locations; do not redefine age, hair, wardrobe, distinguishing object/colour or environment.

TEXT
Critical readable labels/numbers belong to deterministic rendering, not generated images. Keep generated screens, documents, labels and signs blank/unreadable unless the visual does not expose their text. Explicitly include no pseudo-writing/readable gibberish in generated-image prompts.

PAYOFF
The final payoff must visibly RESOLVE the story: transformation, apparent-vs-actual reveal, corrected state, branch reconciliation, or concrete resolution scene. Do not finish with another summary node chain when the resolution can be shown.

FREE-FIRST
Runtime tries reusable/free image routes before paid Fal image fallback. Paid image fallback is allowed only by runtime policy. Paid generated video remains disabled by default. Author every alternate semantically; never use an alternate as permission for unrelated filler.

FINAL CHECK
Before returning, fix: missing scenes; bad beat numbering; too few beats for measured voice duration; preferred==fallback; unusable alternate briefs; timeline used for causality/branching; semantic graph missing required nodes/edges/labels; excessive diagram monotony where illustrations are stronger; recurring identity drift; generated pseudo-text; generic kinetic cards; or payoff that explains instead of visibly resolving.
